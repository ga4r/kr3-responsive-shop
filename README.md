# RunSmart — адаптивная версия

## Контрольная работа №3

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

Магазин пульсометров RunSmart из КР №1, адаптированный под телефоны, планшеты и desktop. Основа — HTML/CSS-проект КР №1, Bootstrap не используется. Тексты, картинки и страницы те же. Все адаптивные правила вынесены в отдельный файл `css/responsive.css`, после адаптации проведена проверка доступности.

## Подключение стилей

На каждой странице:

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<link rel="stylesheet" href="css/style.css">
<link rel="stylesheet" href="css/responsive.css">
```

`responsive.css` подключён после `style.css`, чтобы медиазапросы переопределяли базовые стили.

## Адаптивные решения

- Добавлен файл `css/responsive.css`, адаптивные правила из `style.css` перенесены туда.
- Применён подход Mobile First. В `style.css` описана мобильная версия: везде одна колонка, без sticky-элементов. В `responsive.css` она расширяется медиазапросами `min-width`: 576px, 768px, 1024px и 1280px. Старые медиазапросы `max-width` из КР №1 удалены.
- **Навигация.** На телефоне меню переносится на отдельную строку под логотипом (Flexbox с `flex-wrap`), шапка не прилипает к верху, чтобы не занимать пол-экрана. С 1024px шапка в одну строку и становится sticky. Номер телефона показывается с 1280px, раньше он не помещается.
- **Hero-блок.** На телефоне заголовок 34px и преимущества списком в столбик, с 768px — 48px и в строку, с 1024px — 56px.
- **Сетка карточек (Grid).** На телефоне одна колонка. С 576px `repeat(auto-fill, minmax(240px, 1fr))`: столько колонок, сколько помещается. Популярные товары на главной: 1 → 2 → 4 колонки.
- **Каталог и боковой фильтр.** На телефоне и планшете фильтр стоит над товарами на всю ширину. С 1024px он становится колонкой 270px слева и прилипает при прокрутке. Широкая карточка Polar FT4 на телефоне вертикальная, с 768px — горизонтальная.
- **Страница товара.** На телефоне миниатюры идут строкой под большим фото, фото ниже (320px вместо 480px). С 768px миниатюры слева, с 1024px галерея и описание в две колонки, блок помощи справа.
- **Изображения.** В `style.css` правило `img, video { max-width: 100%; height: auto; }`. Для фото в карточках товаров и для большого фото на странице товара добавлены `srcset` (версии 320px и полная) и `sizes`. Браузер выбирает файл по реальной ширине фото на экране: на desktop карточка узкая (`260px` в `sizes`), и грузится версия 320px; на телефоне карточка во всю ширину (`100vw`), и грузится полная. Проверено во вкладке Network.
- **Форма заявки.** На телефоне поля в одну колонку и способы доставки списком, с 768px — две колонки полей и три карточки доставки в ряд. Поля высотой 48px, между кнопками отступ.
- **Таблицы.** Таблицы обёрнуты в `.table-wrapper` с `overflow-x: auto`. Таблицы на 4 колонки (сравнение моделей, условия доставки) получили `min-width: 560px` и на телефоне прокручиваются внутри обёртки, а не вместе со страницей. Таблица характеристик из двух колонок помещается и так. На телефоне уменьшены отступы в ячейках.
- **Контакты и подвал.** Карточки контактов: 1 → 2 колонки, контакты и форма: 1 → 2 колонки с 1024px. Подвал: 1 → 2 → 4 колонки.
- Для длинных слов и адресов добавлено `overflow-wrap: break-word`.

## Доступность

Что проверено и исправлено:

- Проверен `viewport` на всех страницах и приведён к виду `initial-scale=1.0`.
- Исправлен контраст плейсхолдеров в полях формы: был `#8a8a8a` (3,45:1), стал `#6b6b6b` (5,33:1).
- Исправлен контраст счётчика на активной кнопке категории в каталоге: убрана `opacity: 0.75`, из-за которой контраст был 3,8:1.
- Проверено, что на каждой странице один `h1` и уровни заголовков идут без пропусков.
- Проверены `label` у всех полей форм и `alt` у всех изображений.
- Видимый фокус: общее правило `:focus-visible` с рамкой 3px, у полей формы — своя подсветка.
- Ссылка «Перейти к содержимому» (skip-link) есть на всех страницах, появляется по первому нажатию Tab.
- Модальное окно доступно с клавиатуры: после открытия по Tab фокус попадает на кнопку закрытия и поля окна, а пока окно закрыто, его поля в порядок обхода не входят.
- Ссылки с одинаковым текстом ведут в одно место: ссылка «Контакты» в подвале, которая вела на главную, переименована в «Адрес и телефон» (найдено Lighthouse).
- Навигация размечена через `nav`, у каждого меню есть название (`aria-label` или `aria-labelledby`). ARIA используется только там, где без него не обойтись.

Контраст плейсхолдеров и полупрозрачного текста Lighthouse не проверяет, эти проблемы найдены вручную.

## Lighthouse

Проверка запускалась в браузере (DevTools → Lighthouse) по опубликованной версии на GitHub Pages: категория Accessibility, режим Mobile (эмуляция Moto G Power), Lighthouse 13.5.0, 11.11.2026.

| Страница | Accessibility | Пройдено проверок |
|---|---|---|
| https://ga4r.github.io/kr3-responsive-shop/index.html | 100 | 27 |
| https://ga4r.github.io/kr3-responsive-shop/catalog.html | 100 | 24 |
| https://ga4r.github.io/kr3-responsive-shop/order.html | 100 | 27 |

Ошибок Lighthouse не нашёл. На всех трёх страницах он отметил для ручной проверки пункт «Identical links have the same purpose»: в меню ссылка «Контакты» вела на `contacts.html`, а в подвале ссылка с тем же текстом — на блок контактов на главной. Текст ссылки в подвале заменён на «Адрес и телефон».

В папке `lighthouse/`:

- `accessibility-index.html`, `accessibility-catalog.html`, `accessibility-order.html` — полные отчёты, открываются в браузере;
- `accessibility-report.png` — скриншот отчёта по `order.html`.

## Проверенные ширины

360px, 430px, 768px, 1024px, 1440px.

На каждой ширине проверены шапка, навигация, hero, сетка карточек, каталог с фильтром, страница товара, таблицы, форма заявки, контакты, подвал и модальное окно. Горизонтального скролла всей страницы нет ни на одной странице и ни на одной ширине.
